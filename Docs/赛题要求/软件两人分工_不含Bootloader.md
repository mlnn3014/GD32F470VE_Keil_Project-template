# 2026 CIMC 初赛软件两人分工（不含 Bootloader）

## 1. 分工目标

本分工面向初赛自动评分流程中除 Bootloader 升级以外的 APP 功能实现，覆盖自动评分 A-M 模块：

- A：广播寻址与重启心跳
- B：基础查询
- C：时间设置与回读
- D/E：变比、DAC、阈值设置
- F/G：重启后参数持久化与 DAC 联动
- H：自动上报
- I：告警记录
- J：睡眠唤醒
- K：异常帧处理
- L：修改设备 ID
- M：修改波特率

总体原则：

- 甲负责“通信协议、系统参数、评分主流程”。
- 乙负责“外设采集、业务功能、显示与低功耗”。
- 两人通过统一接口协作，避免在同一模块中交叉修改。
- Bootloader、固件搬运、升级校验等内容不包含在本文分工内。

## 2. 角色划分

| 人员 | 角色定位 | 核心职责 |
| --- | --- | --- |
| 甲 | 协议通信与系统框架负责人 | 负责上位机命令解析、应答组帧、参数持久化、ID/波特率管理、异常帧处理 |
| 乙 | 外设采集与业务功能负责人 | 负责 CH0/CH1/CH2 数据采集、DAC、自动上报、告警、OLED/LED、低功耗唤醒 |

## 3. 甲的详细任务

甲负责“上位机发什么，设备怎么解析、判断和回复”。

### 3.1 RS485 与串口通信

任务内容：

- 使用 USART1 作为比赛通信接口。
- 默认波特率必须为 19200。
- 通信格式为 8 数据位、1 停止位、无校验。
- 实现 RS485 收发方向控制。
- 建立串口接收缓冲区，支持连续 ASCII 字符串帧接收。
- 保证上位机自动测评开始时设备可以被 19200 波特率找到。

对应评分：

- A-01 广播寻找设备
- A-02 发送重启指令
- A-03 等待重启后心跳
- B-03 查询波特率
- M-01/M-02 修改波特率

注意事项：

- 不允许依赖 DAP 虚拟串口。
- 改波特率命令必须先回复 OK，再切换波特率或重启。
- 修改波特率后，需要保证 115200 下继续通信正常。

### 3.2 协议解析

任务内容：

- 解析 ASCII 形式的十六进制协议帧。
- 识别帧头 `A5B6` 和帧尾 `B6A5`。
- 解析设备 ID、帧类型、命令字、报文长度、协议版本、内容、CRC。
- 实现 CRC-16-Modbus 校验。
- 实现报文长度检查。
- 实现设备 ID 匹配判断。
- 对广播地址 `FFFF` 做特殊处理。

对应评分：

- A-01 广播寻找设备
- K-01 CRC 错误帧
- K-02 长度错误帧
- K-03 非法命令字
- L-01 修改设备 ID

注意事项：

- 非广播地址且设备 ID 不匹配时，必须直接丢弃，不返回任何信息。
- CRC 错误、长度错误、未知命令需要返回错误应答帧。
- 所有封装帧通过 ASCII 字符串发送，不是裸 Hex 字节。

### 3.3 应答组帧

任务内容：

- 实现统一应答组帧函数。
- 支持 OK 应答，内容为 `FF`。
- 支持数据应答，如 uint8、uint16、uint32、float、字节数组。
- 支持心跳帧。
- 支持错误应答帧。
- 所有浮点数按 IEEE754 单精度大端序发送。

对应评分：

- A/B/C/D/E/F/G/K/L/M 全部协议相关评分

建议接口：

```c
void protocol_send_ok(uint16_t id, uint16_t cmd);
void protocol_send_error(uint16_t id);
void protocol_send_heartbeat(uint16_t id);
void protocol_send_bytes(uint16_t id, uint16_t cmd, const uint8_t *data, uint8_t len);
void protocol_send_float(uint16_t id, uint16_t cmd, float value);
```

### 3.4 系统管理命令

任务内容：

- 广播寻找设备。
- 设备重启。
- 查询固件版本，初始版本号为 `2.0.1.0`。
- 设置设备时间。
- 查询设备时间。
- 查询设备 ID。
- 设置设备 ID。
- 查询波特率。
- 设置波特率。

对应评分：

- A-01/A-02/A-03
- B-01/B-02/B-03
- C-01
- L-01/L-02
- M-01/M-02

注意事项：

- 设置设备 ID 后，应答帧中的 ID 需要变更为新 ID。
- 查询设备 ID 时，上位机可能使用广播地址。
- 修改设备 ID 后，旧 ID 下发命令不能应答。
- 波特率映射关系：

| 代码 | 波特率 |
| --- | --- |
| `11` | 4800 |
| `12` | 9600 |
| `13` | 19200 |
| `14` | 115200 |

### 3.5 参数持久化

任务内容：

- 建立 APP 参数结构体。
- 使用内部 Flash 或外部 Flash 保存参数。
- 实现参数默认值。
- 实现参数合法性检查。
- 实现参数保存与重启恢复。
- 保存以下参数：
  - 设备 ID
  - 波特率配置
  - CH0 变比
  - CH1 变比
  - CH0 阈值
  - CH1 阈值
  - 告警记录

对应评分：

- F-01/F-02/F-03/F-04
- L-02
- M-02
- I-03/I-04

建议参数结构：

```c
typedef struct {
    uint32_t magic;
    uint16_t device_id;
    uint8_t baud_code;
    float ch0_ratio;
    float ch1_ratio;
    float ch0_threshold;
    float ch1_threshold;
    uint8_t alarm_mode;
    uint32_t crc;
} device_param_t;
```

建议默认值：

| 参数 | 默认值 |
| --- | --- |
| 设备 ID | `0001`，或队伍指定初始 ID |
| 波特率代码 | `13`，即 19200 |
| CH0 变比 | `1.0f` |
| CH1 变比 | `1.0f` |
| CH0 阈值 | 合理默认值，避免上电误告警 |
| CH1 阈值 | 合理默认值，避免上电误告警 |
| 告警模式 | `02`，不主动上报 |

### 3.6 异常帧处理

任务内容：

- CRC 错误时返回错误应答。
- 长度错误时返回错误应答。
- 未知帧类型或非法命令字时返回错误应答。
- ID 不匹配时不应答。

对应评分：

- K-01 CRC 错误帧
- K-02 长度错误帧
- K-03 非法命令字

错误应答格式：

- 帧类型：`FF`
- 命令字：建议按赛题要求使用 `EEEE` 或原始命令字
- 内容长度：`00`
- 协议版本：`02`

## 4. 乙的详细任务

乙负责“数据从哪里来、怎么算、什么时候上报、如何显示和进入低功耗”。

### 4.1 CH0 电位器采集

任务内容：

- 配置板载电位器 ADC 通道。
- 获取原始采样值。
- 根据当前 CH0 变比计算上报值。
- 返回 IEEE754 单精度浮点数。

对应评分：

- B-04 查询 CH0 数据
- D-01 CH0 变比即时生效
- F-01 重启后 CH0 变比持久化

注意事项：

- 上报值必须是“原始采样值 × 当前 CH0 变比”。
- 数据需要合法、稳定，不能出现明显异常跳变。

### 4.2 CH1 DAC 回读

任务内容：

- 配置 DAC 输出。
- 支持设置 `0-4095` 的 DAC 值。
- 确保 PA4 跳接到 PC1 后可 ADC 回读。
- 根据当前 CH1 变比计算上报值。

对应评分：

- B-05 查询 CH1 数据
- D-02 CH1 变比即时生效
- G-01 DAC 联动
- F-02 重启后 CH1 变比持久化

注意事项：

- DAC 设置后，CH1 回读值应与输出变化一致。
- CH1 上报值也必须乘以当前 CH1 变比。

### 4.3 CH2/PT100 温度采集

任务内容：

- 通过 SPI 与 GD30AD3344 ADC 通信。
- 读取 PT100 采样板输出数据。
- 完成温度换算。
- 根据测试板电阻点进行标定。
- 支持基础测试点和进阶测试点的软件补偿。

对应内容：

- 硬件测评中的 PT100 采样板功能演示
- 外部 ADC 单次查询

基础测试点：

| 模拟温度 | PT100 标准电阻值 |
| --- | --- |
| 0°C | 100.00Ω |
| 20°C | 107.79Ω |
| 40°C | 115.54Ω |
| 60°C | 123.24Ω |
| 80°C | 130.90Ω |
| 100°C | 138.51Ω |

建议：

- 先实现 SPI 原始数据稳定读取。
- 再做线性换算。
- 最后做分段线性插值或二阶拟合补偿。

### 4.4 变比与阈值业务

任务内容：

- 设置 CH0 变比。
- 设置 CH1 变比。
- 读取 CH0/CH1 变比。
- 设置 CH0 阈值。
- 设置 CH1 阈值。
- 读取单通道阈值。
- 批量读取 CH0/CH1 阈值。
- 参数变化后调用甲提供的参数保存接口。

对应评分：

- D-01/D-02
- E-01/E-02
- F-01/F-02/F-03/F-04

建议接口：

```c
void ratio_set_ch0(float ratio);
void ratio_set_ch1(float ratio);
void threshold_set_ch0(float threshold);
void threshold_set_ch1(float threshold);
float ratio_get_ch0(void);
float ratio_get_ch1(void);
float threshold_get_ch0(void);
float threshold_get_ch1(void);
```

### 4.5 自动上报

任务内容：

- 支持设置自动上报间隔。
- 间隔映射：

| 代码 | 间隔 |
| --- | --- |
| `01` | 1s |
| `02` | 3s |
| `03` | 5s |

- 启动自动上报。
- 停止自动上报。
- 自动上报内容为 12 字节：
  - UTC 秒级时间戳，4 字节
  - CH0 数据，4 字节 IEEE754 float
  - CH1 数据，4 字节 IEEE754 float

对应评分：

- H-01 自动上报完整测试
- H-02 过程中不响应停止外的其他命令
- H-03 停止自动上报

注意事项：

- 自动上报期间，除停止自动上报命令 `0303` 外，其他普通命令不得应答。
- OLED 第二行应显示 `AutoSample`。
- 采集工作指示灯应常亮。
- 停止后 OLED 恢复 `IDLE`，采集工作指示灯熄灭。

建议接口：

```c
void auto_report_start(void);
void auto_report_stop(void);
bool auto_report_is_running(void);
void auto_report_poll(void);
```

### 4.6 告警与日志

任务内容：

- 设置是否主动上报告警。
- CH0/CH1 每次采集时判断是否超过阈值。
- 超阈值时保存告警记录。
- 主动告警模式下，立即输出告警字符串。
- 非主动告警模式下，只保存，不主动输出。
- 支持查询最近 10 条告警记录。
- 支持清除告警记录。

对应评分：

- I-01 开启主动告警
- I-02 触发告警并验证
- I-03 关闭告警后再触发
- I-04 清除告警记录

告警字符串格式：

```text
2026-01-01 12:00:00 | CH0 | 10.50 | 11.12
```

注意事项：

- 告警主动输出和告警查询返回都是纯 ASCII 字符串，不走协议帧。
- 查询无告警时返回 `empty`。
- 最近 10 条按时间倒序返回。
- 告警记录需要持久化。

### 4.7 低功耗睡眠与唤醒

任务内容：

- 收到睡眠命令后，先回复 OK。
- 进入 MCU 深度睡眠。
- 使用 RTC 闹钟 10 秒自动唤醒。
- 唤醒后输出字符串。

对应评分：

- J-01 睡眠后自动唤醒

唤醒字符串：

```text
instrument wakeup
```

注意事项：

- 唤醒字符串不走协议帧。
- 测评时需要电流表可观察电流变化。
- 睡眠期间不要手动复位。

### 4.8 OLED 与 LED

任务内容：

- OLED 始终双行显示。
- 第一行显示队伍编号。
- 第二行显示状态。
- APP 区域空闲时显示 `IDLE`。
- 自动采集上报时显示 `AutoSample`。
- 系统状态 LED 从进入 APP 开始以 1s 为单位闪烁。
- 采集工作 LED 自动上报时常亮，其余时刻熄灭。

对应内容：

- 赛题系统架构要求
- 自动上报过程辅助验证
- 视频演示观感

## 8. 重点风险

### 8.1 通信帧发送形式

协议帧是十六进制结构转 ASCII 字符串发送，不是直接发送二进制 Hex。

错误示例：

```text
直接发送字节 0xA5 0xB6
```

正确示例：

```text
发送字符 'A' '5' 'B' '6'
```

### 8.2 ID 不匹配处理

非广播地址且设备 ID 不匹配时，必须静默丢弃，不返回错误帧。

### 8.3 自动上报期间命令响应

自动上报期间，除停止自动上报外，不要响应普通命令。否则 H-02 会扣分。

### 8.4 字符串输出不要封帧

以下内容直接输出 ASCII 字符串：

- 告警主动上报
- 告警查询结果
- 睡眠唤醒 `instrument wakeup`

### 8.5 改 ID 和改波特率是破坏性测试

这两个功能建议最后联调：

- ID 改错会导致后续命令无法匹配。
- 波特率切换失败会导致后续测评全部通信失败。

## 9. 抢分建议

优先级从高到低：

1. 先完成 A/B/C/K：设备能被上位机稳定识别，协议错误处理正确。
2. 再完成 D/E/F/G：变比、阈值、DAC、持久化，这部分分数稳定。
3. 然后完成 H：自动上报有 10 分，必须重点做。
4. 接着完成 I/J：告警和睡眠唤醒。
5. 最后完成 L/M：修改 ID 和波特率，放到最后做破坏性联调。
